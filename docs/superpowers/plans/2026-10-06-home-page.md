# Home Page — Implementation Plan

**Goal:** Add a new Home page at `/` that matches `docs/superpowers/mockups/2026-10-06-home.html`
exactly, and move the current orders dashboard (`src/pages/Dashboard.tsx`) to `/orders`, labelled
**Orders** in the sidebar.

**Decisions (from the user):**
- Top strip: Sessions, Total sales (৳), Orders, **Conversion rate**, Live visitors.
- Globe pin: cities of **live visitors**, latest page view.
- Cards: **rotate by what needs attention**, top three by urgency; insight cards fill empty slots.

---

## 1. Route rename (no behaviour change)

- `src/App.tsx`: `/` → new `Home`; `/orders` → existing `Dashboard`.
  `/orders/new` and `/orders/:id` are more specific and keep working.
- Sidebar (`AppSidebar.tsx`, Main Menu): `Home` (`/`, new id `home`) first, then
  `Orders` (`/orders`, keeps id `orders`), Overview, Ask Edith, Business Analytics.
- Back-navigation that means "the orders list" moves to `/orders`:
  `OrderDetail.tsx:164`, `AbandonedDetail.tsx:254` (keeps its `fulfillmentTab` state).
  Auth, onboarding, NotFound, PrivacyPolicy, `AdminRoute`/`PublicRoute` redirects stay on `/` (Home).
- Sidebar logo link stays `/`.

**Verify:** existing Dashboard, OrderDetail and AbandonedDetail tests updated for `/orders`;
new test that `/` renders Home and `/orders` renders the orders dashboard.

## 2. Visitor coordinates (additive migration)

Live visitors already join to `analytics_sessions` (city, country). Missing: coordinates.

- Migration `supabase/migrations/<ts>_analytics_session_coordinates.sql`: add nullable
  `latitude numeric(8,5)`, `longitude numeric(8,5)` to `analytics_sessions`
  (with range checks); extend `record_analytics_hit` to store `p_entry->>'latitude'/'longitude'`.
  Additive only; run `npm run verify:supabase-baseline` and invoke the `supabase` skill first.
- `server/websiteAnalytics.js` `parseTrackerAnalyticsHit`: accept and validate
  `x-vercel-ip-latitude` / `x-vercel-ip-longitude` (finite, in range), pass them in `entry`.
- Fallback: `server/bdPlaces.js` — static map of Bangladeshi division/district names (and
  common spellings) to coordinates, used when a session has no stored coordinates.
- RPC `live_visitor_locations(p_org_id, p_window_seconds)` (service role only, same grants
  as `count_live_visitors`): live `all`-bucket sessions joined to `analytics_sessions`,
  returning city, country, lat, lon, last path, last_seen_at — **no session ids, IPs or visitor ids**.
  Limit 20, newest first.

**Verify:** migration test (pattern of `liveVisitorPresenceMigration.test.ts`); parser tests for
valid, out-of-range and missing coordinate headers; `bdPlaces` lookup tests.

## 3. `GET /api/home/summary` (Analytics section of `server/index.js`)

Standard guard: `getToken` → `getUser` → 401 → `getUserOrg`; every query filtered by `org_id`.
Returns, for **today (Dhaka)** versus **yesterday up to the same time**:

| Field | Source |
|---|---|
| `sessions`, sparkline | `analytics_website_report` totals + hourly |
| `sales`, `orders`, sparklines | same aggregation as `/api/analytics` (reuse its helper, don't duplicate) |
| `conversion_rate` | `ordered_sessions / sessions` from the website report |
| `live` | existing `countLiveVisitors` + new `live_visitor_locations` |
| `quick_actions` | counts for Send to courier, Reply to inbox, Review fraud flags |
| `attention` | ranked card list (section 4) |

- **Role:** team members get sessions, live visitors, quick actions and cards; `sales`,
  `orders`, `conversion_rate` and money-bearing card details are `null` for non-admins
  (the UI blurs them, matching Dashboard.tsx:1349).
- Each source is fetched in parallel and fails independently (a failed source returns `null`,
  not a 500) — analytics must never break the page.
- Short server cache (30 s, existing `createTtlCache`, keyed by org) — no Redis.

**Verify:** route tests for 401, team-member redaction, org filter on every query, partial-failure.

## 4. Attention cards (`server/homeAttention.js`, pure function)

Input: the counts gathered in section 3. Output: ordered list of cards
`{ kind, title, body, count, cta: { label, to }, preview }`. Rank by fixed severity, then count:

1. **Fraud holds** — `order_protection_reviews.status = 'on_hold'` → `/order-protection` (admin only).
2. **Ready for courier** — the dashboard's "pending" queue definition (reuse it, don't redefine) → `/orders`.
3. **Unanswered inbox** — `social_conversations.unread_count > 0` → `/inbox/facebook` etc.
4. **Inbox orders to review** — new `social_inbox_orders` not yet sent → `/inbox/orders`.
5. **Pending returns** — the `/api/nav/counts` definition → `/returns`.
6. **Abandoned checkouts** — today's recoverable checkouts → `/orders` (abandoned tab).

A card shows only when its count > 0. Remaining slots fill with insight cards:
**Top varieties** (sales by product, last 7 days) and **Live now** (cities on the site).
Always exactly three cards.

**Verify:** unit tests for ordering, zero-count hiding, admin-only filtering, insight backfill.

## Open risks

- `analytics_website_report` is admin-only today; the new endpoint calls the RPC directly, so team
  members must not receive money fields — covered by the redaction test.
- Vercel geo headers are approximate (ISP location); pins say the city, never a street.
- Sessions recorded before the migration have no coordinates; the `bdPlaces` fallback covers them.

## Engineering review notes

- **Conversion rate definition.** `ordered_sessions / sessions` counts only website visits that
  ended in an order, while the Orders metric counts every channel (website, inbox, manual).
  That is intentional: conversion is a website metric. The tooltip says "Website visits that ordered".
- **"Ready for courier" lives in the client today** (Dashboard's `pending` queue filter). Step 4
  first extracts that predicate into a shared module used by both the dashboard and the summary
  endpoint, with a test proving the counts match. No second definition.
- **Route move is SPA-only.** Express has no `/orders` page route, so the change is confined to
  React Router; API paths are untouched.
- **Payload privacy.** `live_visitor_locations` returns city-level data only; the endpoint never
  exposes session ids, visitor ids or IPs.
- **Cost.** One summary request every 30 s per open Home tab, cached 30 s server-side; the website
  report RPC already runs on a rollup, so no new heavy queries.
